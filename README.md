# CS2 饰品行情 QQ 群机器人

在 QQ 群里 @机器人 即可查询 CS2 饰品价格、7天涨跌幅，并获取选品推荐。数据源为 [CSQAQ](https://www.csqaq.com/home) 官方开放 API，机器人本体基于 QQ 官方机器人平台（WebSocket 长连接）。

## 快速开始

### 1. 注册凭证

**CSQAQ（数据源）**
1. 打开 https://csqaq.com/home 注册并登录
2. 点击头像 → 查看 ApiToken 令牌
3. 在 CSQAQ 后台绑定本机/服务器的**出口 IP 白名单**

**QQ 机器人**
1. 打开 https://q.qq.com 用 QQ 扫码登录 → 创建机器人应用
2. 进入「开发设置」→ 获取 `AppID` 与 `AppSecret`（Secret 只显示一次，立即保存）
3. 在「权限配置」中开启 **群聊消息** 权限
4. 确认机器人状态为 **已上线**（开发中的机器人无法收发消息）
5. 创建一个 QQ 群，把机器人拉进群，并开启「机器人主动发言」权限

### 2. 安装与配置

```bash
# Python 3.10+（建议 3.11）
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt    # Windows
# .venv/bin/pip install -r requirements.txt      # Linux/macOS

cp config.example.yaml config.yaml
# 编辑 config.yaml，填入 CSQAQ api_token、QQ appid/secret
```

### 3. 验证数据源

```bash
.venv/bin/python scripts/fetch_once.py --pages 2
# 若输出饰品行情 JSON 即表示 CSQAQ 连接成功
```

### 4. 启动机器人

```bash
.venv/bin/python main.py
```

看到日志 `robot 「xxx」 已连接` 后，到群里 @机器人 测试：

```
@机器人 /帮助
@机器人 /推荐
@机器人 /推荐 超跌
@机器人 /价格 爪子刀 外表生锈
@机器人 /排行 涨
```

> 提示：在群里首次 @机器人 后，日志会打印 `group_openid`，把它填入 `config.yaml` 的 `push.group_openids` 即可开启每日早报推送。

## 饰品异动雷达（三层池 + 综合评分）

基于 PRD V1.0 实现的全自动异动发现系统：**全市场发现 → 活跃池跟踪 → 超级异动高频监控 → 自动降级 → 智能推送**。

### 三层监控池（全自动升降级，无需手动添加）

```
B 全量发现池(约 1~1.5 万件,180 分钟一圈)    ← 多维度榜单深翻,发现长尾异动
   │  评分 ≥ 55 自动升级
A 活跃监控池(约 800 件,3 分钟批量跟踪)        ← 榜单发现每 10 分钟,成员独立跟踪
   │  评分 ≥ 70 或 5min 极端波动自动升级
S 超级异动池(≤50 件,30 秒一轮)              ← 高频确认(同步落盘口时序),TTL 120 分钟防占满
   │  连续 3 轮 <55 或超时 → 自动降回 A
```

### 五维评分（0~100，可解释）

`价格变化(5m/30m/1h) + 供需(求购增/在售减/盘比) + 买卖价差 + 短中期趋势 + 历史价格位置`

- **数据边界**：CSQAQ 单品详情可提供 Steam `turnover_number`（成交数量），但需校验 `period_at` 时效；无数据或过期时不伪造成交量，需求侧仍表述为「求购数量增加 + 在售数量减少」
- **缺失不填 0**：历史不足时按可用权重归一化 + 置信度折扣，冷启动新品不会被误判强异动
- 6 类异动：突然拉升 / 突然跳水 / 需求增强 / 供应减少 / 上涨供需背离 / 下跌后企稳

### 成交量/盘口量价解算（`/分析` 与 `/异动` 共用）
> 说明：有新鲜 Steam 成交统计时优先使用真实成交数量及其周期变化；CSQAQ 成交周期缺失或超过 48 小时时，自动降级为求购/在售盘口活跃度，并在输出中标明口径。
> `/分析` 与 `/关注` 的普通/周期监测数量口径为六平台合计（BUFF、Steam、悠悠有品、C5、IGXE、ECO）；价格触发仍使用 BUFF 价格，异动雷达评分继续使用其独立的 BUFF 榜单口径。

| 关系 | 盘口 | 价格 | 结论 |
| --- | --- | --- | --- |
| 量增价涨 | 增 | 涨 | 低位=启动，中位=健康上行，高位=防诱多 |
| 量缩价跌 | 缩 | 跌 | 低位=筑底，中位=正常回调，高位=下跌中继 |
| 量平价涨 | 平 | 涨 | 惜售锁仓，若无接力要防变盘 |
| 量平价跌 | 平 | 跌 | 阴跌格局，承接乏力 |
| 量缩价涨 | 缩 | 涨 | 无量上涨，动能衰竭 |
| 量增价跌 | 增 | 跌 | 放量下跌，恐慌出逃；低位可视作最后一跌 |
| 量平价平 | 平 | 平 | 多空僵持，方向不明 |
| 量增价平 | 增 | 平 | 放量滞涨，多空激战；低位偏吸筹，高位偏出货 |

| 特殊形态 | 条件 | 含义 |
| --- | --- | --- |
| 地量地价 | 极低盘口活跃度 + 低位 + 价格平/跌 | 卖无可卖，关注止跌 |
| 无量空涨 | 极低盘口活跃度 + 价格上涨 | 高位常是诱多陷阱 |
| 无量空跌 | 极低盘口活跃度 + 价格下跌 | 缺乏买盘承接，流动性危机 |
| 天量天价 | 极高盘口活跃度 + 高位 + 价格上涨 | 经典顶部风险 |
| 底部放量 | 极高盘口活跃度 + 低位 | 聪明钱入场信号 |
| 高位放量滞涨 | 极高盘口活跃度 + 高位 + 价格横住 | 出货 / 对倒风险 |

`手套武器箱 500 -> 550`：在高基线下会被解算为 `量增价涨 / 强信号`；若处于低位则偏“启动”，若处于高位则偏“防诱多”。

### 关键设计

- **B 池走「榜单深翻」而非 goods_index**：goods_index 仅存中文名，批量查价接口只认英文名（market_hash_name），逐个转换需 2.5 万次请求不可行；榜单每页 100 件自带完整行情，10 个排序维度（售价/求购价×升降 + 1/7/30 日涨跌×升降）深翻即可覆盖全部活跃品
- **全局限流**：异动模块独立令牌桶（默认 13 req/min），B 池约 1.4 + A 发现约 1 + A 跟踪约 5.3 + S 池约 2，按令牌桶排队执行；短线优先保障 A/S，B 负责慢速发现
- **告警去重**：分级冷却（L2 10min / L3 5min / L4 3min），评分较上次提升超阈值可突破冷却
- **推送**：达到 L2 预警自动推送 VIP 群（纯文本，QQ markdown 不支持 `**` 加粗）

### 配置

`config.yaml` 的 `anomaly:` 段，所有参数（池规模/频率/评分权重/等级阈值/升降级/冷却/限流/**质量门槛**）均可调。

> **质量门槛**（评分入口直接拦截）：低价款在低价区波动百分比虚高（0.04→0.03 即 -25%），会把评分顶到 L2 刷屏，而高价正经品反而少触发。系统先执行基础质量闸门，再执行异动求购深度资格；池内低求购成员有有限观察期，不会掩盖或永久绕过真实质量清理：
> - `min_price`（默认 ¥5）：主参考价 <5 元，多为无流动性噪声；
> - `min_buy_num`（默认 1）：实时求购数 =0 即死盘，无真实需求；批量求购字段缺失/沿用时跳过该项，不把未知当成 0；
> - `min_anomaly_buy_num`（生产默认 50）：BUFF+悠悠求购合计低于 50 的新品不进入异动评分/推送；已有成员进入有限低深度观察期（默认 60 分钟），超时移出池；
> - `min_sell_num`（默认 3）：在售挂单 <3 件，无真实交易市场（如 1 个挂单的 ¥500 品，深度虽够但本质是薄盘噪声）；
> - `min_depth`（默认 ¥200）：在售侧市场深度 `sell_num × price` <200 元，薄盘无真实交易深度；
> - `min_listing`（默认 10）：在售+求购总数 <10，视为无流动性噪声；
> - `implausible_30m`（默认 200%）/ `implausible_1h`（默认 300%）：|30m| 或 |1h| 价格变化超过此值，几乎必是 CSQAQ 陈旧/错误基线（如 5m 不动却显示 1h +3231%），判为数据故障直接拦截。
> - `buy_carried_forward`：批量查价无求购字段时沿用历史值，仅用于维持 BUFF+悠悠时序，不参与求购变化、买卖盘比、周期阶段或依赖求购的质量判定；`/价格`、`/分析` 和普通关注不受异动深度门槛影响。

## AI 智能回复（可选）

默认自然语言会走本地关键词意图识别；配置 `llm` 段后，自然语言由 LLM 理解意图并调用工具查 **真实数据**（价格/推荐/播报/排行），再组织自然语言回答，支持多轮追问，所有数字均来自 CSQAQ，不会编造。

```yaml
llm:
  enable: true
  base_url: "https://open.bigmodel.cn/api/paas/v4"   # 智谱(免费) / 腾讯混元 / DeepSeek 三选一
  api_key: "你的APIKey"                                # 智谱 open.bigmodel.cn 注册即送 GLM-4-Flash 免费额度
  model: "glm-4-flash"
```

- 斜杠指令（`/价格` 等）始终走本地，确定性操作不受 AI 影响
- AI 超时或异常时自动降级为本地意图识别，机器人不会失联
- 若想更省 token，可将 `route_all_nl` 设为 `false`，仅本地识别不出的意图才走 AI

## 7x24 小时稳定运行

### 方案 A：systemd（Linux 服务器）

```bash
sudo cp deploy/service/cs2qqbot.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now cs2qqbot
sudo systemctl status cs2qqbot     # 查看状态
journalctl -u cs2qqbot -f          # 查看日志
```

服务配置了 `Restart=always`，进程崩溃会自动拉起；QQ WebSocket 断线由 botpy 自动重连。

### 方案 B：Docker

```bash
docker build -t cs2-qq-bot .
docker run -d --name cs2-qq-bot --restart=always \
  -v /opt/cs2-qq-bot/config.yaml:/app/config.yaml:ro \
  -v /opt/cs2-qq-bot/data:/app/data \
  -v /opt/cs2-qq-bot/logs:/app/logs \
  cs2-qq-bot
```

### 方案 C：Windows（本机长期挂机）

```bat
:: 创建一个 start_bot.bat 放在项目根目录
@echo off
cd /d %~dp0
:loop
.venv\Scripts\python.exe main.py
timeout /t 10 /nobreak >nul

```

## 采集频率与反爬说明

- CSQAQ 官方 API 免费开放（注册即得 Token），比直接爬网页稳定得多
- 客户端内置**请求节流**（默认 1s/次）与**失败重试**（3 次退避），避免触发限频
- 默认每 15 分钟抓取一次排行榜（3 页 × 100 条 = 最多 300 条样本），可按需调整 `config.yaml`
- 全量饰品数据接口（2.5 万+ 条）仅对企业用户开放，如需全量可联系 CSQAQ 站长

## 扩展建议

- **历史趋势**：优先走 SteamDT 单品 K 线（`marketHashName`，日K 可拿到 365 根）；`/分析` 按 T+7 持有视角解读（周期分层：7日/30日趋势·位置·全平台流动性·中期结构为持有依据，30m 量价仅短线预警），SQLite 快照只做兜底
- **更多策略**：在 `bot/analyzer/recommender.py` 中添加策略函数并注册到 `STRATEGIES`
- **关键词触发**：修改 `config.yaml` 的 `qq.keywords` 增加自然语言触发词
- **持仓监控**：用 `getPriceByMarketHashName` 接口（≤50 个/次）做自选饰品盯盘
- `/分析` 新增**左侧/右侧买点候选**（基于 20 日线结构与低位深跌，白盒标注候选/确认/失效/风险），**仅供观察，不构成任何买卖建议**
